# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # Vite dev server with HMR
npm run build    # production build to dist/
npm run preview  # serve the built dist/
npm run lint     # eslint over the repo
```

There is no test setup in this project (no test runner, no test files). Don't invent one unless asked.

## What this is

A macOS-desktop-themed personal portfolio: React 19 + Vite + SCSS (plain `.scss` files imported per component, no CSS modules, no Tailwind). The whole page is a fake desktop — wallpaper `body` background, a top `Nav` menu bar, a bottom `Dock`, and draggable/resizable "app" windows.

## Architecture

**Window system.** Three pieces:

- `src/components/windows/registry.js` declares every window once: `{ id, title, icon, dockClass, component, preload, defaultSize }`. **This is the only place a window is defined** — `App` and `Dock` both render from it. `component` and `preload` come from one `chunk(() => import('./X'))` call: a `React.lazy` plus the memoised loader behind it.
- `src/hooks/useWindowManager.js` owns all window state: `{ open, mounted, minimized, maximized, z, geometry, restore, userSized }` per id, plus a derived `topmost` and `open / close / focus / minimize / toggleMaximize / setGeometry / toggleFromDock / refit`. All updaters are pure; the next z-index is computed as `max(z) + 1` inside the updater rather than from a ref.
- `src/components/windows/MacWindow.jsx` is the shared chrome. Geometry is **controlled** — the manager owns x/y/width/height and `MacWindow` only reports changes back through `onGeometry`. That is what makes maximise, restore, and surviving a close/reopen work.

**Window components are content-only.** `Github.jsx`, `Notes.jsx`, etc. return just their inner markup; `App.jsx` wraps them in `MacWindow`. They receive `wm` (the manager), `id`, and `mobile` props — most ignore all three, but `Cli.jsx` uses `wm`/`id` for `open`, `close`, and `exit`, and `mobile` to shrink its type and prompt.

**Adding a window is one edit:** add an entry to `registry.js`. Optionally add it to `LAYOUT` in `Dock.jsx` to control where its icon sits.

**Behaviours worth knowing:**
- *Lazy mount, then permanent.* A window isn't in the tree until first opened (`mounted`), and stays mounted after — hidden with `display: none`. So terminal history and scroll survive a close, and the Spotify iframe/PDF never load unless asked for. **Don't "optimise" this back into conditional rendering.**
- *One chunk per window.* Because each `component` is a `React.lazy`, the entry bundle carries only the shell (~80 kB gzip); the terminal emulator, the syntax highlighter, the PDF object and the Spotify iframe arrive with their window. Two prefetches hide the split: `Dock` calls `def.preload` on `pointerenter`/`pointerdown`/`focus`, and `App` calls `preloadAll` in a `requestIdleCallback` after first paint — so the `.window-loading` Suspense fallback is essentially never seen. `preload` swallows its own rejection (a failed *warm-up* must not be an unhandled rejection); the real failure still reaches the error boundary when the window renders.
- *Error boundaries.* `src/components/ErrorBoundary.jsx` (a class — there is no hook form). `App` wraps **each window's content** in one, outside the `Suspense`, so a throw or a missing chunk shows a labelled `role="alert"` panel inside that window's frame and the rest of the desktop keeps working; `main.jsx` wraps the whole app as a backstop.
- *Layering.* Nav is `z-index: 1000`, dock `900`, windows from `10` up, boot overlay `5000`. Windows live in `.desktop`, which is `position: relative` because `react-rnd`'s `bounds="parent"` measures against it.
- *`userSized`.* False while a window still has the geometry `spawn` gave it. `refit` (on every viewport change) **re-spawns** those to suit the new size, but only clamps a window the visitor has dragged or resized. Without it, a window first opened on a phone stayed 320 px wide after the viewport grew.

**The open/close animation.** Windows grow out of their dock icon when opened and collapse back into it when closed. Four pieces, and it is deliberately *not* part of the window manager — that stays a pure state machine:

- `src/hooks/useWindowAnimation.js` is the engine. Opening is **detected** (`open` going false→true in a layout effect, so every route in — dock, terminal `open`, the panel's Replay — is covered without knowing about the hook); closing is **intercepted** (`anim.close(id)` plays first and calls the manager's `close` only on finish, so the window is still genuinely open, and therefore still rendered, for the animation's duration — no "is closing" flag to keep in sync). `App` splices `close` and `toggleFromDock` over the manager's own and passes that composed object down, so the traffic lights, Esc, and the terminal's `close`/`exit` all animate.
- It animates the inner `.window` section, **never the `Rnd` wrapper** — react-rnd drives that wrapper's `transform` to position it. `MacWindow` hands the element out through a `frameRef` callback ref.
- Keyframes are sampled in JS (30 steps) and played through `element.animate()` at `easing: 'linear'`. That is not laziness: the genie needs the vertical collapse to lead the horizontal squeeze, i.e. two different curves inside one transform, which no single CSS timing function can express. Closing is the open curve run backwards through time, so the two can never drift apart.
- `src/data/windowAnimation.js` holds the defaults, the easing curves and the `CONTROLS` schema; the settings panel's **Window** tab renders its whole form from that array (grouped by `section`, rows hidden by `showIf`), and `useAnimationSettings` persists to localStorage with a sanitiser — a hand-edited entry must never reach the keyframe builder and produce `scale(NaN)`. **Adding a knob is one line in DEFAULTS plus one entry in CONTROLS**, nothing else.

Worth knowing: dock icons carry `data-window-id` because the animation looks them up by id — the dock's order is `LAYOUT`'s, not the registry's. Minimise and restore are deliberately left instant. A close commits on the animation's `onfinish`, so in a **backgrounded tab** the document timeline freezes and the close only completes when the visitor returns; clicking the red button again calls `finish()` and commits immediately, and a dock click mid-collapse cancels the close and grows the window back rather than minimising it.

**The wallpapers.** Eight *live* ones — canvas scenes that answer the cursor. There is no still-photo option: it was removed, and with it every "is this one live?" branch in the app. Split across four files so none of it competes with first paint:

- `src/data/wallpapers.js` is the **catalogue** — id, name, hint, preview gradient. It is data-only and tiny because it rides in the entry bundle: the settings schema reads it for its enum, and the picker renders a tile per entry. `WALLPAPERS[0]` is the default, exported as `DEFAULT_WALLPAPER`.
- `src/data/wallpaperScenes.js` is the **engine** — `{ backdrop, init(w,h,q), draw(s,c), click(s,x,y) }` per scene, imported only by `LiveWallpaper` and therefore only in that lazy chunk. All of a scene's mutable state lives in the object `init` returns, so switching scenes is just calling `init` again; `q` is a quality factor (0.5 on a phone) that scales particle counts.
- `src/data/wallpaperVoices.js` is the **ambient audio** — one Web Audio graph per scene, synthesised, so the soundtrack is essentially zero bytes of payload. A voice is built as `VOICES[id](ctx, destination, options)` and exposes `g` (its own gain, for cross-fading), `stop()`, and optionally `update(p)` and `hit()`. A scene with no entry here is simply silent. **Vinyl Hour is the one voice that plays a real file** (see *The record* below); everything else is oscillators and filtered noise.
- A scene may also export **`voice(s)`** — extra fields merged into what the loop passes `update`, so a scene can tell its voice what it is *doing* (the needle is up, the platter is at a third speed) without `LiveWallpaper` knowing anything about either. `update` still gets `{ x, y, hot }` regardless.
- `src/components/LiveWallpaper.jsx` is the loop. Always mounted, but lazily.

**What paints before the canvas can.** `body` carries a CSS gradient — a copy of the default scene's own `backdrop` — so the desktop is never black in the moment between first paint and the `LiveWallpaper` chunk landing, and the real scene resolves *out* of it rather than cutting over it. It costs nothing and needs no preload, which is why `index.html` no longer has any. **Change the default wallpaper and that gradient in `app.scss` changes with it.** `public/mac-wallpaper.jpg` is still in the repo but no longer used by the app at all: it is only the stand-in `og:image` until a real one exists.

**Things about the live wallpaper that are load-bearing:**
- *Nothing goes through React state.* The loop writes the canvas and one `transform` on the headline directly, like `BootSequence`. Sixty re-renders a second behind five open windows is the one thing this app can't afford.
- *The pointer is tracked on `window`, not on the element.* The wallpaper is `pointer-events: none` at `z-index: 0` under `.desktop` (which is `z-index: 1` for exactly this reason), so it can never take an event from a window, the dock or the menu bar. It reads events as they pass and asks `overDesktop(target)` — a `closest()` against `.window, .mobile-window, .react-draggable, nav, .dock, .settings-panel, .boot, .desktop-hints` — whether the cursor was over free desktop. **That selector is the contract**: renaming any of those classes silently makes clicking a window fire the wallpaper's interaction.
- *The frame is wrapped in a `try`.* A throw inside rAF is invisible to the error boundaries and would freeze a canvas over the whole desktop; instead the loop stops and the backdrop gradient stands in. The boundary around it is `silent`, so a failed chunk leaves the `body` gradient standing rather than papering the desktop with an alert.
- *The loop stops when it can't be seen* — hidden tab, or `paused`, which `App` sets on mobile whenever a window is up, since those are full-screen and opaque.
- *Sound is off by default and never autoplays.* Turning it on is itself a gesture, but the setting is remembered, so a reload arrives with no gesture behind it and the context comes back `suspended` — `resumeOnGesture` retries on the visitor's first interaction. Without it the menu bar shows an unmuted speaker over silence.

**The tour.** `src/components/DesktopHints.jsx` — four small cards that play once, straight after the boot intro, ringing the wallpaper, the dock, the settings gear and the sound button in turn. Everything this desktop does is hidden behind an icon, and a visitor who pokes at nothing sees a screenshot of a Mac.

- Copy and selectors live in `src/data/hints.js`, like every other piece of content. A hint names its target with a **CSS selector**, and the component measures that element from the live DOM — so restyling the dock or moving the gear can't leave the ring behind, and a selector that matches nothing degrades to a centred, ringless card rather than a ring in the corner. `HINT_LEAD` and `HINT_HOLD` are the whole timing.
- **It is not a modal**: no dimming layer, no focus trap, `pointer-events: none` except for the card's own button — the first card asks the visitor to click the desktop, so the desktop has to stay live underneath. That's the other half of listing `.desktop-hints` in `overDesktop`.
- *Touching a real control ends it* (a `pointerdown` inside `nav, .dock, .window, .mobile-window`), because at that point the visitor has stopped reading. A click on empty desktop deliberately does **not** — that is the tour being obeyed, not skipped. Esc ends it too; `App`'s one Esc chain is now tour → settings panel → frontmost window.
- Only the step index is React state. Position is written straight to the three nodes from a layout effect, the way `BootSequence` paints, and the entrance and the progress bar are CSS animations restarted by keying each element on the hint id. The hold **pauses while the tab is hidden** — a `setTimeout` doesn't, so a site opened in a background tab would otherwise play its whole tour to nobody.
- It runs exactly as often as the intro does, and for the same reason: `App` decides both from `hasBooted()` at first render, so a reload gets neither and tomorrow's visit gets both.

**Settings.** `src/components/SettingsPanel.jsx`, opened from the menu bar, with three tabs: **Wallpaper** (which one, motion, ambience), **Fonts**, **Window** (the open/close animation — this used to be the whole panel). Both schemas — `data/desktop.js` and `data/windowAnimation.js` — describe controls identically and render through the same `SettingsField`, so a knob is still one line in DEFAULTS plus one entry in CONTROLS; the `tab` field decides where it lands. The three pickers (wallpaper, interface font, headline font) are hand-written because each has to *preview* what it selects. Reset belongs to whichever schema the visible tab edits, and the two settings objects have separate storage keys so resetting one can't discard the other. Both hooks are thin wrappers over `usePersistentSettings`, which owns the storage and the sanitiser.

**Fonts.** `src/data/fonts.js` holds two independent sets. `UI_FONTS` restyle the desktop through the `--ui-font` custom property (defaulted on `:root` in `app.scss`, set inline on `<main>` by `App`) and are **system stacks only** — that setting applies on every wallpaper, so it has to weigh nothing. `DISPLAY_FONTS` style the headline drawn over the wallpaper and *are* webfonts; `ensureDisplayFonts()` injects the Google Fonts link on demand, called only by `LiveWallpaper` **while the headline is switched on** and by the Fonts tab opening. Either way it is behind the wallpaper chunk and so can never hold up first paint — which is the whole reason it isn't a `<link>` in `index.html`. Turn the headline off and the site asks Google for nothing. The boot sequence sits outside `<main>` and so always keeps the stock macOS face.

**The menu bar's sound button** sits beside the Wi-Fi icon and toggles `sound` in the desktop settings — the same value the panel's Ambience row edits. Every wallpaper has a voice, so it is never a dead button. Volume itself stays in the panel: a menu-bar volume popover was built and then deliberately taken back out, so **don't re-add one**. Its styles, and the settings gear's, live in `nav.scss` and **not** `settingsPanel.scss` — that file ships with the panel's lazy chunk, and both buttons are on screen from first paint, so styling them there left them as raw browser buttons until Settings was first opened.

**The record.** Vinyl Hour plays an actual audio file, layered under the synthesised crackle, hiss and pops. Four pieces:

- `BUNDLED_TRACK` in `wallpaperVoices.js` points at `public/audio/vinyl-hour.mp3`, through `asset()` like every other public path referenced from JS. **That file is not in the repo** — drop one in and it plays; leave it out and the scene is surface noise with no music. Every failure (missing file, 404, undecodable) resolves to `null` and is swallowed: `loadTrack` never rejects, because a wallpaper soundtrack is not something to put an error in front of a visitor for.
- A visitor can put on their own instead, from Settings › Wallpaper › The record (shown only while Vinyl Hour is up). The Blob goes to IndexedDB via `src/utils/trackStore.js`; the settings object holds only `trackName`, which is both what the panel prints and what tells `LiveWallpaper` to go and read the store again. Nothing is uploaded. `trackStore` never throws — private mode falls back to a copy in memory that lasts the page view.
- **The needle gates the music**, not the surface noise: `click` toggles `s.playing`, the scene's `voice(s)` hook reports it, and the voice ramps the track's gain. It starts *down* — turning ambience on and hearing only crackle until you happen to click reads as a broken button. The platter's speed is the track's `playbackRate`, so dragging the cursor across slows and detunes the music like a hand on the record.
- The tonearm's angle is **solved** from where the stylus should land (parked just outside the rim, or on the outer groove) by the law of cosines, not hand-tuned. The version that drew the arm outward from its pivot at a fixed angle left it floating in space beside the platter at most aspect ratios.

**The boot intro.** `src/components/BootSequence.jsx` — a fixed overlay above everything (`z-index: 5000`) that plays a macOS cold boot on the session's first load: Apple logo over a progress bar, the twelve-language `hello` cycle, a flash, then the desktop. Split across three places:

- The component owns the whole 8.6 s timeline (the `T` table, all times in ms against `BASE_RUNTIME`; a different `runtime` prop scales them together via `k`). It **paints straight to the DOM from a `requestAnimationFrame` loop** rather than through React state — ten elements re-rendering at 60 fps while the window chunks prefetch is the one place in this app where that costs something. So `bootSequence.scss` holds only the still frame plus the starting opacities.
- `src/components/bootGate.js` owns the `sessionStorage.hasBooted` key: `App` reads it to decide whether to render the intro at all, `BootSequence` writes it when the sequence ends. Session-scoped on purpose — a refresh mid-terminal shouldn't replay it, tomorrow's visit should.
- `app.scss` owns the desktop's half. `App` puts `.booting` on `<main>` (menu bar and dock held at `opacity: 0`, `<main inert>` so neither is clickable or tabbable behind the veil) and adds `.revealing` when the component reports the reveal. The two entrances are CSS animations delayed off that moment and scaled by `--boot-k`, so re-timing the intro re-times them. They animate the `translate` **property**, not `transform`, because `.dock` already uses `transform` to centre itself — the two compose instead of overwriting each other.

Worth knowing: the wallpaper is deliberately *not* animated, because it is a `body` background that paints before React runs (see the preloads in `index.html`) — the reveal lifts the black veil off the real desktop rather than fading in a second copy of it. A tap or keypress anywhere skips to the flash, `prefers-reduced-motion` gets a plain 600 ms fade off black with no logo or greetings, and the rAF callback is wrapped in a `try` that cuts to the desktop: a throw in there is invisible to the error boundaries and would otherwise freeze an opaque veil over the entire portfolio.

**The mobile layer.** `src/hooks/useIsMobile.js` owns the 768 px breakpoint and is the single JS source for it; the same number is repeated in the stylesheets as `@media (max-width: 767px)` because SCSS can't read it. Below the breakpoint:

- `MacWindow` skips `react-rnd` completely and renders a `.mobile-window` frame filling `.desktop` minus the dock (`--mobile-dock-h` in `app.scss`, which must stay in sync with the dock's real height). Geometry is ignored, so there is no drag, resize, or zoom button.
- `App` shows **only `wm.topmost`** — full-screen windows are opaque, so stacking them would just hide the ones behind. Closing the front one reveals the next.
- The dock becomes a full-width bottom tab bar. Its sizes are tuned so all 9 icons fit a 390 px screen (icon 2.35rem, gap .25rem); `overflow-x: auto` is the fallback for narrower phones — a tenth icon means shrinking those again. Magnification is gated behind `@media (hover: hover)` so it can't stick after a tap.

**Accessibility contract.** Dock windows are `<button>`s and dock links are real `<a href>`s (external ones carry `target="_blank" rel="noopener noreferrer"`); traffic lights are `<button>`s whose 24 px hit target wraps a 12 px dot drawn with `::before`. Each window is a `role="dialog"` named by its title and takes focus when it opens, Esc closes the frontmost one, and `app.scss` defines the single `:focus-visible` ring. **Keep new interactive elements as real buttons or links** — the previous `<div onClick>` version was invisible to keyboards and screen readers.

**The menu bar's left half is content, not chrome.** It carries the name, the role from `profile.js`, and five real `<a>`s — GitHub, LinkedIn, LeetCode, Resume, Email — reachable **without opening a window**, so a visitor who never touches an icon still leaves with the résumé and a way to make contact. It used to read `File · Window · Terminal`: three menus with nothing behind them, in the most valuable strip on the page. **Don't put decorative menus back.** Resume points at the PDF itself (through `asset()`), not at the window that frames it. Below 940 px the role drops out and below the 768 px breakpoint the links do too — the dock already carries mail and LinkedIn as icons, and the bar only has room for a name and a clock on a phone.

**The greeting window.** `GREETING` in `App.jsx` — the window that opens by itself once the intro is done, so nobody lands on an empty desk. It is Skills, because it is the smallest frame in the registry and so answers "what can he do" without burying the desktop it sits on; set the constant to `null` to go back to a bare desktop. It goes through `wm.open`, the same call the dock makes, so it grows out of its dock icon with no special case in the animation. Three guards, each earning its place: **after** `boot === 'off'` (or it animates from a dock still sliding into place behind the veil), **not on a phone** (a window there is full-screen and opaque, and would hide the desktop, the wallpaper and the tour on arrival), and **not if anything is already open** (the intro is skippable, so a visitor can beat it to the dock — taking focus back from a window they chose would be worse than an empty desk). The `greeted` ref is set *before* the last two checks: this is one decision taken as the intro ends, not a standing rule, or a narrow window later dragged wider would spawn the greeting minutes in.

**Dock.** `src/components/Dock.jsx` builds its icons from a `LAYOUT` array interleaving registry windows with plain external links (calendar, mail, LinkedIn, LeetCode). A dock click calls `toggleFromDock`, which launches, restores, raises, or hides — **never closes**. Closing belongs to the red button alone.

**Content sources.** All copy lives in `src/data/`, not in components — a project is described once and read by both the Github window and the terminal:
- `src/data/projects.js` — featured projects (`{id, title, description, tags[], repoLink, demoLink, image}`). `demoLink` and `image` may be `null`; `Github.jsx` renders a generated monogram tile when `image` is null.
- `src/data/profile.js` — `profile`, `contact`, `skills`, `experience`, `education`, `achievements`. **`experience` and `education` are intentionally empty arrays**; `Cli.jsx` only registers those commands when the arrays are non-empty, so placeholder employers can never reach a visitor. Fill the arrays to enable the commands.
- `Notes.jsx` fetches `public/note.txt` at runtime and renders it via `react-syntax-highlighter`. It mirrors the `skills` export in `profile.js` — keep both in sync. **Import the `light` build by path** (`react-syntax-highlighter/dist/esm/light`) and register only the languages used, and import the theme by path too — the package root registers all ~190 languages and the `styles/hljs` barrel pulls in every theme. That was 870 kB of the old bundle.
- `Resume.jsx` renders `public/resume.pdf` in an `<object>` with a mobile fallback. `public/resume.pdf` is the real resume (replaced 2026-08-09; it had been a downloaded sample for an unrelated person). It carries facts the app also states in `src/data/` — education, skills, project blurbs — so **when the PDF is updated, re-check `profile.js` and `projects.js` against it.**
- `Spotify.jsx` embeds a hardcoded Spotify playlist iframe.
- `Cli.jsx` builds its command map from `src/data/`; `open`, `close`, and `exit` call through the `wm` prop. `react-console-emulator` styles itself inline, so type size, padding and `white-space` can only be set through its props — a stylesheet can't reach them. It also renders its own unlabelled `<input>`, so `Cli.jsx` sets that element's `aria-label` in an effect.

Icons come from `public/doc-icons/` and `public/navbar-icons/`, referenced through `asset()` (see **Deployment** below) — never as a bare `/doc-icons/github.svg`.

## Deployment

GitHub Pages, served from a **subpath** (`https://dakshchauhan2005.github.io/Portfolio/`), which is the one fact that shapes all of this:

- `vite.config.js` sets `base` to `/Portfolio/` for `build` **and** `preview`, `/` for `dev`. `preview` has to be tested separately via `isPreview` — it runs with `command === 'serve'`, so without that check it would serve at `/` the very files it just built pointing at `/Portfolio/`, and 404 every asset. Override without editing code: `BASE_PATH=/ npm run build` for a custom domain or a `<user>.github.io` repo.
- **`src/utils/asset.js` is the rule that matters.** Vite rewrites absolute asset URLs in `index.html` and in CSS `url()`, but **not inside JS string literals** — a bare `'/doc-icons/github.svg'` stays bare in the bundle and 404s off the domain root. So *every* `public/` path referenced from JS goes through `asset()`: the registry icons, the dock's link icons, Nav's and BootSequence's `<img>`s, `Notes`' `fetch`, `Resume`'s PDF URL. **Adding a new public-dir reference in JS means calling `asset()`** — the stylesheets and `index.html` need nothing.
- The OG/Twitter image and `og:url` in `index.html` are **absolute hardcoded URLs**, not base-relative: scrapers don't resolve relative paths. They don't follow `base`, so a change of deploy target means editing those lines by hand.
- `.github/workflows/deploy.yml` runs lint → build → upload → deploy on push to `main`, via `actions/deploy-pages`. It copies the built `index.html` to `404.html` (a safety net only — the app has no router) and `public/.nojekyll` stops Pages running the files through Jekyll.
- One-time repo setup: **Settings → Pages → Source: "GitHub Actions"**. Without it the workflow builds and then fails at the deploy step.
- `eslint.config.js` gives `*.config.js` the Node globals, since `vite.config.js` reads `process.env`.

**Images.** There are none on the critical path any more — the wallpaper is a CSS gradient until the canvas takes over, so there is no LCP image to preload and `index.html` preloads nothing. The only `public/` image the deploy still needs is `mac-wallpaper.jpg`, referenced **only** by the absolute `og:image`/`twitter:image` (which must stay a JPEG — scrapers don't all handle WebP, and they don't resolve relative paths either). Replace it with a real 1200×630 OG screenshot and that file goes.

## Things to know

- `src/main.jsx` renders `<App />` **without** `<StrictMode>` — deliberate, since double-invoked effects interfere with the window/terminal components. Don't add it back.
- **Never write placeholder content into `src/data/`.** If a fact isn't known, leave the array empty and let the command hide itself. The repo previously shipped fabricated projects and "Company A" employment; that was the single worst thing in it.
- Content + hygiene, the window manager, mobile + a11y, performance, and deploy config are all done. **Still open: CI running lint + build on PR (the deploy workflow only runs on push to `main`), custom domain, Lighthouse.** Also still open and needing the owner, not code: filling `experience`/`education` in `src/data/profile.js` (the education facts are now in `public/resume.pdf` — BBD University, B.Tech CSE, 2023–2027 — and just need transcribing), a README screenshot, and a real OG image (it currently points at the wallpaper).
- Build is ~279 kB entry (88 kB gzip) plus one chunk per window, one for `SettingsPanel`, one for `DesktopHints` (~3 kB) and one for `LiveWallpaper` (~25 kB). If a change pushes the entry chunk back over ~300 kB, something got pulled out of a lazy chunk — check what the entry now imports. The usual culprit is the wallpaper split: importing `wallpaperScenes.js` from anything the entry reaches drags all eight scenes' drawing code in with it.
- ESLint config allows unused vars whose names match `^[A-Z_]` (so unused component/constant imports won't error, but unused lowercase locals will).
